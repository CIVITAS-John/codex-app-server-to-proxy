# Codex compatibility

The proxy targets one app-server contract at a time. The current runtime dependency is `@openai/codex` **0.155.1**, pinned exactly in `package.json`. Its generated experimental TypeScript and JSON Schema contract is checked into `protocol/`, with the version and generation commands recorded in `protocol/VERSION.json`. The package-owned executable supplies normal startup and protocol generation; an explicit `--codex-path` must report the same version. A different Codex release needs a contract review before it can run behind the proxy.

| Compatibility boundary                    | Current behavior                                                                                                                                       | Consequence of a Codex update                                                                                                                                             |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| JSON-RPC and generated types              | Generation uses the pinned package with `--experimental`; `npm run check:protocol` compares a regenerated temporary tree with the checked-in contract. | Review method, notification, and field changes before changing translation or policy code. Regenerate with `npm run generate:protocol`; do not hand-edit generated files. |
| Model catalog and direct client functions | The proxy installs a temporary Responses Lite override for 0.155.1.                                                                                    | Recheck direct and parallel function-call behavior before removing the override. A passing schema check alone does not establish model behavior.                          |
| Codex home and authentication             | A proxy-owned Codex home is shared across roots; only `auth.json` is synchronized from the ordinary Codex home.                                        | Review on-disk cache/config formats and token handling before reusing that home with a new pin.                                                                           |
| Continuation state                        | Each root has a separate durable response store with schema version 0.                                                                                 | Review the persisted record format and restart behavior; migrate an incompatible format explicitly or reject it without rewriting it.                                     |

## Temporary model catalog override

Codex 0.155.1 can route models marked `use_responses_lite` through code mode, turning declared client functions into nested callbacks. The proxy clones `models_cache.json` into `models.no-responses-lite.json`, sets `use_responses_lite` to `false` for every model, and removes `tool_mode` from entries that originally used Responses Lite. The pinned model metadata no longer contains `supports_parallel_tool_calls`, so the conversion cannot depend on that former field. The source cache remains Codex-owned and unchanged by this transformation.

A marked top-level `model_catalog_json` block in the selected home's `config.toml` points to the clone. Installing it preserves unrelated configuration but replaces any previous top-level catalog selection. The override is specific to the current pin; remove it only after a reviewed runtime and opt-in live contract show that direct, batched client functions work without it. See [user-facing behavior](../README.md#temporary-responses-lite-override) and the [app-server protocol reference](codex-app-server.md#pinned-compatibility-note).

At each new proxy process, startup makes one bounded catalog refresh attempt through a private app-server with a fresh temporary Codex home. It copies ordinary configuration without the static catalog selection and uses the selected home's credentials. Only a newly written cache with the pinned client version and nonempty valid models replaces the selected cache. Startup then rebuilds the clone and restarts the private app-server so its startup-only catalog selection takes effect. On refresh failure, the previous cache is retained with a warning; readiness still requires a usable override. Recovery of an app-server within the same proxy process does not repeat the fetch. `GET /v1/models` sees the resulting catalog frozen for that process and starts no model turn.

## Homes, credentials, and continuation state

| Data                  | Default location                                                      | Compatibility rule                                                                                                                                                                                                                                                                                            |
| --------------------- | --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Codex home            | `~/.codex-openai-proxy/codex-home`, or `--codex-home`                 | Shared by proxy roots, separate from the ordinary `~/.codex` home. It contains the login, model cache, override, and Codex configuration.                                                                                                                                                                     |
| Authentication source | `$CODEX_HOME/auth.json` or `~/.codex/auth.json`                       | Default `--sync-auth always` copies only a missing or strictly newer source credential. `--sync-auth never` leaves the proxy home independent. A recovered login can write back only to an existing older source after a pulled credential proved unusable. Shared rotating refresh tokens remain race-prone. |
| Continuation store    | A root-hash namespace under `~/.codex-openai-proxy`, or `--state-dir` | Stores opaque response-to-thread mappings and pending client tool calls for 30 days. The current schema is version 0; malformed or foreign-version records are not trusted. Uninstalling the npm package does not remove this state.                                                                          |

The unversioned proxy home was reviewed for the 0.154.0 to 0.155.1 upgrade: the proxy's persisted filenames and state schema did not change, and the catalog override preserves unknown cache metadata. This supports reuse of an existing proxy home for this pin, but does not establish compatibility with a later Codex release. See [authentication](../README.md#authentication), [continuation](../README.md#continue-a-codex-thread), the [architecture](architecture.md), and the [repository guide](development.md) for operational details.

## Verification boundary

Child-agent starts can arrive as `subAgentActivity` instead of `spawnAgent`. The proxy preserves only `kind` and `agentThreadId` in the existing `x_codex` activity extensions; agent paths remain private and legacy collaboration output is unchanged. The nonce-handoff contract requires exactly one child start and its raw provider completion. It verifies the child reply through `agentsStates` or, after completed activity, that child's completed thread history via `thread/read`, which starts no model work. The targeted live scenario passed on 2026-09-22 with `gpt-6-luna` under the existing 32-response maximum; six other scenarios were skipped. Build and test type-checking passed. Synthetic normalization coverage was added but not run during this targeted live verification.

The default `npm run check` gate is deterministic and offline. It checks generated protocol drift, types, translation, and failure paths; `npm run test:package` separately checks the packed CLI offline. Neither gate can prove model choices, authentication against a real account, or remote npm publication. The separately selected live configuration uses `gpt-6-luna`, runs serially, and caps the core contract at 32 deduplicated upstream responses plus two for the system-prompt contract. The release checklist tracks external CI, registry, and live evidence separately. Do not infer a normal model-call count from the ceiling. See [live test instructions](development.md#live-contract-tests) and [release checklist](../RELEASE.md).

When changing the Codex pin, use the repository's `update-codex` workflow, inspect the generated diff and the behavior boundaries above, run the offline and packed-package gates, and record the compatibility and persistence decision here. Live verification remains an explicit, separately budgeted action.
