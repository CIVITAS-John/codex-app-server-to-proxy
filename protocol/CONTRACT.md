# Stage 01 compatibility contract

This contract targets `codex-cli 0.153.4`, pinned by the exact `@openai/codex` runtime dependency. The checked-in TypeScript and JSON Schema artifacts were generated from that package-owned executable with `--experimental`; they are the wire-type source of truth. Regenerate them with `npm run generate:protocol` after changing the package pin.

## Request fields

| Field | Classification | Mapping |
| --- | --- | --- |
| `model` | Standard, required | `thread/start.model`; must match for native reuse — a difference selects fresh execution with the requested settings. |
| `reasoning_effort` | Standard | Validates `none`, `minimal`, `low`, `medium`, `high`, `xhigh`, or `max` and maps the selected value to `turn/start.effort`; `turn/start.summary` defaults to `"detailed"` so exposed reasoning summaries are emitted, while explicit `none` requests `summary: "none"`; must match for native reuse — a difference selects fresh execution with the requested settings. Individual models may support only a subset. |
| `messages` | Standard, required | Text-only role history is validated. A trailing user message becomes the turn `input`; any other trailing message is injected as history and the turn starts with empty `input`. A continuation may end in a tool message only when it resolves that response's pending dynamic calls; a ready continuation ending in a tool message is rejected with HTTP 409 `tool_results_without_pending_call` rather than flattened into user text. Tool messages before the terminal block are completed earlier rounds: a fresh thread injects each one as the `function_call`/`function_call_output` pair the Responses item format requires, because `role: "tool"` is not an item type. |
| `tools` | Standard | Function tools become experimental `dynamicTools`. Their locale-independent, UTF-16-code-unit-key-sorted canonical JSON SHA-256 must match for native reuse because the pinned protocol cannot replace tools on `thread/resume` or `turn/start`; a difference selects fresh execution with the requested tools. |
| `tool_choice` | Standard, restricted | Omitted and `auto` expose the declared dynamic tools. `none` is accepted by omitting dynamic tools. `required` and named choices are rejected because this app-server has no faithful per-turn equivalent. |
| `stream` | Standard | `true` streams SSE. `false` buffers the same event pipeline and emits one response. |
| `stream_options.include_usage` | Standard | Defaults to true in this proxy, a deliberate deviation from OpenAI's opt-in default. Unless explicitly false, an otherwise empty final choices array carries attributable usage before `[DONE]`. |
| `previous_response_id` | Nonstandard continuation field | Preference for native continuation; clients should supply the complete intended transcript. Resolves a durable local mapping and preflights `thread/resume` when local admission permits reuse; local unavailability — an unknown, expired, or superseded selector; a changed model, reasoning, cwd, tools, or policy binding; active client tools without raw-response capability on the current transport; or local thread contention — executes the supplied complete transcript on one `thread/start`, reported as `x_codex.threadReused: false`. A fallback transcript must be completely paired (every assistant tool call answered by its immediately following tool results, no orphan results) or the request fails with a typed 400 before any RPC. Remote read/resume/inject/start failures never trigger a second execution. Tool results may omit the field by default when their `tool_call_id` values uniquely identify one unexpired pending-tool mapping — unknown, expired, or ambiguous lookup IDs select fresh execution while duplicate IDs remain a typed 400 — and server configuration can require it. |
| `x_codex` | Nonstandard extension | Optional `cwd`, `sandbox`, and `web_search` controls. `cwd` is canonicalized inside the configured root; sandbox accepts `disabled`, `read-only`, `workspace-write`, or explicit `danger-full-access`; web search accepts `disabled`, `cached`, `indexed`, or `live`. Defaults are root, `disabled`, and disabled web search. Public sandbox `disabled` is realized as native `read-only` plus `environments: []`, and therefore requires managed policy to allow native `read-only`. |
| `temperature`, `top_p`, `n`, `stop`, `max_tokens`, `max_completion_tokens`, `presence_penalty`, `frequency_penalty`, `logit_bias`, `logprobs`, `top_logprobs`, `seed`, `response_format`, `modalities`, `audio`, `prediction`, `service_tier`, `store`, `metadata`, `user`, `parallel_tool_calls` | Ignored with warning | These harmless unsupported top-level fields are not forwarded. Emit one structured `unsupported_chat_fields_ignored` warning per request containing the sorted field names. |
| Any other unknown top-level field | Ignored with warning | Apply the same single `unsupported_chat_fields_ignored` warning. Unknown fields within `messages`, `tools`, `stream_options`, or `x_codex` remain malformed or unsupported. |

## Protocol mapping

| App-server method/event | Proxy behavior |
| --- | --- |
| `initialize`, `initialized`, `configRequirements/read` | Initialization precedes traffic. Experimental capabilities are enabled by the generated contract. Managed policy allowlists are loaded when available; method-not-found means unrestricted proxy defaults, while unknown allowlist entries are skipped. |
| `model/list` | `GET /v1/models` queries every visible-model page from the active authenticated pinned app-server before returning an OpenAI-shaped list. Each entry uses the accepted Codex `model` slug as `id`; `created: 0` and `owned_by: "openai"` are synthetic compatibility placeholders because app-server does not supply them. When installed, the temporary Responses Lite override supplies the frozen catalog; otherwise app-server's ordinary catalog does. Listing starts no Codex thread or turn. |
| `thread/start` | Creates a new thread only after validation succeeds. Supplies `model`, `ephemeral: false`, `experimentalRawEvents: true`, and `dynamicTools` when enabled, plus canonical cwd, native sandbox, approval settings, and per-thread `config.web_search`. Disabled mode additionally supplies sticky `environments: []`. |
| `thread/resume` | Preflight for every mapped continuation and explicitly reapplies canonical cwd, native sandbox, approval settings, and `config.web_search`. The method has no generated `environments` or raw-event field; the following `turn/start` reapplies disabled mode, while raw completion boundaries remain available only if this transport previously started the thread. Local admission selects fresh execution for active client tools when this transport lacks the thread's raw boundaries (a reattached post-restart thread), before any source RPC; HTTP 502 `dynamic_tool_batch_boundary_unavailable` remains an in-stream defense only. Restored token usage is ignored for new-response attribution. |
| `turn/start` | Starts one turn on a non-busy thread and explicitly applies requested reasoning effort plus cwd, approval settings, and the full sandbox policy so sticky prior-turn state is never inherited accidentally. Disabled mode additionally supplies per-turn `environments: []`. |
| `item/agentMessage/delta` | Standard `choices[0].delta.content`. |
| `item/tool/call` request | Centrally routed by thread to exactly one active owner. Callbacks without a matching direct raw call remain client-executable dynamic calls; callbacks matching a raw call are deduplicated because app-server may serialize them behind the first unanswered request. The proxy persists the completed batch and interrupts the turn (`turn/interrupt`, which flushes usage within milliseconds on the pinned app-server). The interrupt cancels opened requests app-server side, so they are left unanswered: tool results are delivered via continuation, not by resolving the request. A failed interrupt durably invalidates the batch and fails the HTTP response. A late ownerless callback from an interrupted thread is ignored when its thread has a durable pending batch, and answered `-32602` correlation mismatch otherwise. |
| `rawResponseItem/completed` | Internal `x_codex` control event. A direct `function_call` whose name matches a declared client tool supplies its call ID, name, arguments, and provider output order for the standard `tool_calls` batch. IDs already present in submitted assistant history are replay, not new calls, and are excluded. Other provider-native raw items remain private. |
| `rawResponse/completed` | Internal `x_codex` control event that closes one upstream dynamic-tool batch. Direct raw calls and unmatched callbacks preceding it are merged in arrival order; duplicate call IDs and matching raw/callback pairs are deduplicated. Its nullable per-request usage, usage metadata, and provider-native payload are not exposed through Chat Completions. |
| reasoning delta and completed-item events | Nonstandard direct compatibility field `choices[0].delta.reasoning`; completed reasoning items backfill only text not already streamed by the same item, never standard `content` and never a response-side `x_codex` field. |
| command, file-change, MCP, plan, web-search, collaboration, and other supported internal activity | Function-shaped `tool_calls` plus the nonstandard direct compatibility field `tool_results`. These calls are observational, are not client-executable dynamic calls, and do not cause `finish_reason: "tool_calls"`. For `webSearch`, an incomplete `item/started` placeholder is withheld; the completed item's `query` and `action` form the call arguments, and its `results` form `tool_results[].result.content` when present. |
| `thread/start.instructionSources` / `thread/resume.instructionSources` | Nonstandard response-level `x_codex.instructionSources`. Preserve the environment-native string paths exactly and return an explicit array on every successful response. Aggregate output includes it once; SSE includes it only on the first chunk. A malformed or missing required app-server field fails before HTTP success is committed. |
| Successful `thread/start` / `thread/resume` setup | Nonstandard response-level `x_codex.threadReused`. Return `false` after a successful new thread start and `true` only after the mapped existing thread resumes with its expected ID and accepts the next turn. Aggregate output includes it once; SSE includes it only on the first chunk. |
| `thread/tokenUsage/updated` | Attribute a response from the exact cumulative `total` gained since its persisted pre-response snapshot. Fresh threads start from zero; continuations use the prior response mapping's optional `usageTotal`. A missing baseline, incomplete counters, or any cumulative reset permanently falls back to the exact `last` values for that response. Missing or malformed attribution data emits `usage_attribution_degraded` at most once per reason per response. Each response then persists the exact boundary its successor subtracts from: the newest total it reported, or the boundary it started from when app-server attributed nothing to it. A `total` arriving without an attributable `last` never advances that boundary, because no response reported its delta. Replayed resume usage is ignored. |
| `turn/completed` | Finalize mapping. Standard finish reason is `stop`, or `tool_calls` when the turn was interrupted at a client dynamic-tool batch. Internal activity does not change the finish reason. |
| `thread/status/changed` | The matching transition to `idle` is every turn's transport boundary — completed turns reach it naturally, tool-call turns through the proxy's interrupt — and correlated usage received after `turn/completed` is still consumed. When a response has no usage, `idle` opens a 250 ms grace window for one trailing usage flush; when usage is already known, `idle` ends the wait immediately. A fixed ten-second deadline caps the entire collection, including any grace, and normally serves as the backstop when `idle` never arrives; the request timeout can abort sooner. Omitting unavailable usage loses nothing: the pending mapping's boundary carries the unreported requests to its continuation. Abort, transport loss, ingress overflow, grace expiry, or backstop expiry emits one `usage_unreported` warning and ends collection without retracting the turn's frames or its continuation mapping. |
| `error` notification or failed `turn/completed` | Only a TurnError `codexErrorInfo: "usageLimitExceeded"` maps to HTTP 429 `rate_limit_error`, normally `usage_limit_exceeded`; other turn errors retain their existing mapping. The failed quota request performs at most one memoized, abortable `account/rateLimits/read` for enrichment. |
| JSON-RPC error | Retains the existing JSON-RPC mapping; `error.data` is not inspected for quota classification. Overload `-32001` maps to retryable HTTP 503 before headers. A malformed JSON-RPC `error` object fails closed. |
| `account/rateLimits/read` | Internal, failure-only quota enrichment; never a public quota endpoint or proactive gate. Prefer `rateLimitsByLimitId.codex`, then `rateLimits`, and choose the latest future reset among exhausted primary/secondary windows; include `individualLimit` only when `spendControlReached`. Stale-percent fallback is permitted only for `rate_limit_reached`; rolling windows never infer a workspace reset. Explicit workspace credit exhaustion always maps `insufficient_credits` with no reset. An explicit workspace usage cap maps `workspace_usage_limit_exceeded` only when no trustworthy individual spend-control reset exists; with `spendControlReached` and a valid future `individualLimit` reset, it remains `usage_limit_exceeded` with reset metadata. Vox Agents treats both workspace codes as non-retryable. A trustworthy reset adds nonstandard `error.x_codex.reset_at` in Unix seconds and, before a response is committed, the matching integer-seconds `Retry-After`; malformed or failed lookup omits both while retaining the typed 429. The proxy never sleeps, queues, consumes reset credit, retries, or replays. |
| approval requests | Use `auto_review` when effective policy allows; immediately answer unexpected requests with decline. Approval state is diagnostic only. |
| `serverRequest/resolved` | Ignored: the app-server cancels its own `item/tool/call` requests as part of the interrupt, and the proxy has already captured the batch it needs. Duplicate client results are rejected against the durable mapping. |
| account read/login events | `account/read` detects auth. `account/login/start` with ChatGPT opens the returned URL when possible; one interactive-terminal fallback may print it. Plaintext logs may retain the URL, while continuation state does not. |

Unknown and explicitly diagnostic-only app-server events are retained only as bounded, plaintext debug diagnostics and are not exposed over HTTP. This includes the pinned unstable `item/autoApprovalReview/*` notifications and `item/commandExecution/terminalInteraction`, whose payloads do not satisfy the public item-progress contract. Each diagnostic records the method name and parameter keys once per app-server transport, and diagnostics are capped at a fixed number of distinct methods for that transport's lifetime.
`protocol/fixtures/exposed-events.ts` is the authoritative generated-protocol-typed manifest of notification and server-request types intentionally handled by the HTTP translation, including complete nested `Turn` values and server-request parameters; diagnostic-only events are excluded. A contract test requires every runtime-handled notification to appear in this corpus.

## SSE mapping

The iterator is primed before HTTP 200. The first chunk has `delta.role: "assistant"` and response-level `x_codex.instructionSources` plus `x_codex.threadReused`. Text uses `delta.content`. Exposed reasoning uses the nonstandard direct `delta.reasoning` field. Calls use function-shaped `delta.tool_calls`; internal progress and terminal output use the nonstandard direct `delta.tool_results` field and repeat the matching call so each result is self-correlating. The final choice has an empty delta and `finish_reason` of `stop` or `tool_calls`. Unless explicitly disabled with `stream_options.include_usage: false`, reported usage follows in a chunk with `choices: []`. A successful stream ends with `data: [DONE]`. An immediate quota error is JSON HTTP 429; after visible output, an error stream emits exactly one typed SSE error event and closes without `[DONE]`.

The nonstandard direct compatibility result shape is:

```json
{"tool_results":[{"id":"item","type":"function","function":{"name":"tool_name","arguments":"{}"},"result":{"status":"started|in_progress|completed|failed","content":"optional value","error":{"message":"optional bounded error","code":"optional code"}}}]}
```

## Errors and continuation invariants

Errors use `{"error":{"message":"...","type":"invalid_request_error|conflict_error|rate_limit_error|server_error","param":"field or null","code":"stable_code","x_codex":{"reset_at":1234567890}}}`. The optional integer-seconds `x_codex.reset_at` is only quota-error enrichment and is not standard Chat Completions. Maintained HTTP continuation tests pin continuation statuses and codes. A local-unavailability fallback invokes exactly one `thread/start`; validation and live-pending result mismatches still perform no thread or turn work, and no failure on either execution path — remote read, resume, injection, or start failures included — ever triggers a second execution within the same request. Lookup may persist a lazy transition to expired.

Response IDs are `chatcmpl_codex_` plus at least 128 bits of URL-safe cryptographic randomness. The unreleased schema-version-0 store follows `schemas/response-mapping.schema.json`: it contains a wrapper version and flattened response records with exact thread bindings, one of the `ready`, `pending_tool`, `expired`, or `superseded` lifecycle states, creation/expiry times, optional full pending-call metadata (`pendingCalls`: call ID, tool name, and the exact JSON-stringified arguments the response emitted), and the optional exact cumulative `usageTotal` boundary the next response subtracts from. Pending call IDs are derived from `pendingCalls` rather than stored separately. The usage boundary is the newest total the response reported, or the boundary it started from when it reported none, so an all-zero value is meaningful rather than absent. Records missing fields required by the current shape are dropped on load. The newest completed response ID is stored per thread; an older or superseded selector executes the supplied transcript on a new thread without recovering hidden native history. `thread/fork(lastTurnId)` remains unproven and is not a v1 feature.

Native reuse requires exact model, reasoning effort, canonical tool set, canonical cwd, and effective-policy fingerprints. Effective policy includes sandbox, web-search mode, approval policy, and approval reviewer. The proxy reapplies matching settings on resume and turn start rather than relying on sticky thread state. A changed binding — model, reasoning effort, cwd, tools, or effective policy, where `tool_choice: "none"` normalizes to no active tools and changes a tool-bearing binding — selects fresh execution of the supplied transcript on a new thread with the requested settings; the pinned app-server protocol cannot represent a changed tool set on `thread/resume`, so the replacement thread is started deliberately rather than rejected. A pending tool batch is durable: its call metadata is persisted before the originating HTTP response ends, the Codex turn is interrupted at the batch, and nothing about it is process-local, so tool results survive proxy restarts (including implicit selection by `tool_call_id`) and expire only with the normal mapping retention. The continuation resumes the idle thread, durably marks the pending mapping non-replayable, injects each call as a complete `function_call`/`function_call_output` pair via `thread/inject_items` (the interrupted turn never persisted its own `function_call` item, and an unpaired output is silently ignored), and starts the next turn — with empty `input` when the request ends in a tool message. Submitted client tool output is injected only; it is never echoed as response `tool_calls` or `tool_results`, and replayed `dynamicToolCall` lifecycle items are ignored. If the replay-guard write fails, injection does not begin and a corrected retry remains safe. Injection failure or a crash after the guard fails the request, and the tombstoned mapping is never re-injected because the effect on the source thread's history is unknowable; a retry carrying the complete transcript executes it on a fresh thread rather than resuming or returning 410, so duplicate pairs remain impossible. The later `superseded` bookkeeping is best-effort and cannot re-enable the expired record. One store instance remains authoritative for the server lifetime. Thread admission and dynamic-tool routing are acquired atomically as one owner-specific lease. Transport replacement and shutdown dispose the old coordinator generation, reject callbacks until close, and close the old transport; buffered post-close frames are ignored and stale executions cannot record completed responses.

A tool-ending continuation is valid only against a pending-tool mapping. A ready mapping has no pending call to receive that result and returns HTTP 409 `tool_results_without_pending_call` without resuming or starting a turn.

## Live compatibility boundary

The opt-in Stage 07 live contract runs serially with only `gpt-5.6-luna`. It retains high-reasoning role-history SSE, three consecutive full-history client-defined tool-result continuations, a restart continuation whose active-tool step now expects fresh fallback with delivered tool batches, and default disabled-capability coverage. It also requires a platform-neutral `workspace-write` turn that reads a nonce through `commandExecution`, writes it through `fileChange`, and verifies the file on disk; a live `webSearch` lifecycle with filesystem and agents unavailable; and exactly one `spawnAgent` lifecycle whose completed `agentsStates` entry hands the exact nonce to the parent and whose child thread emits `rawResponse/completed`. Missing child raw completion fails the contract. The filesystem/web backend uses an isolated Codex home with `[agents] enabled=false`; the spawn-only backend uses a separate home with `[agents] enabled=true`. Agent availability is process configuration, not a per-request `x_codex` field.

The live cost guard counts every distinct `(threadId, responseId)` reported by `rawResponse/completed` across parent and child threads, app-server restarts, and both isolated backends, with a hard maximum of 32 provider responses. No normal count is claimed before an authorized live calibration. These expanded scenarios have not been live-executed. Exact request mapping and denials remain deterministic offline coverage; one live selection does not validate every reasoning-effort, sandbox, or web-search value. Browser launch fallback and `thread/fork` fidelity remain unproven; branching remains unsupported.
